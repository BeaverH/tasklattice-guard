Default is a local protection baseline: it retains the reviewed local Rules and needs no detection-model configuration. Installation, baseline regression and default traffic handling make no model calls. Model Policies, including jailbreak and content safety, remain available in the Policy Library for explicit use in other Guardrails; local Rules do not replace their semantic detection.

Platform health checks model bindings required by the pinned baseline and enabled published routes. Unused model assignments and historical versions do not make a local installation unhealthy. Administrators may activate failed or untested model bindings; their actual test results remain visible, and activation does not turn them into passing results. **A callable Model** and **a Rail actively using it** are different states.

<a id="platform-model-steps" />

## Configure in dependency order

1. Register the service URL and credentials in [Providers](/settings/providers), then check connectivity. Private-CA and related TLS settings apply only to that Provider. After a change, test the affected Models again.
2. Register a physical model in [Models](/settings/models) and make a real test call. Discovery alone does not prove callability.
3. In [Guardrail Catalog](/settings/guardrail-catalog), assign a Model to a capability such as `content_safety.input` or `jailbreak.input`. Input and Output bindings are independent and the protocol must fit the capability contract.
4. Validate behavioral samples, save and activate the assignment, then confirm Runner application in [platform health](/settings/health). A Models test call alone does not prove that content-safety or jailbreak behavior passes validation.

Remote Detector modules have a 30-second execution deadline. Capability probes use the same upper bound; a longer Model timeout does not extend a Guardrail's deadline. Timeouts fail closed and do not count as successful detection or permit publication.

For Grounding with `nvidia/nemotron-3.5-lightning-30b-a3b` on NVIDIA's hosted API, the adapter disables optional thinking so the model can return its JSON classification within that budget. This option does not change the portable Policy definition or requests to other model services. Validate your own positive and negative cases before release.

<a id="platform-model-boundary" />

## Control-plane and data-plane boundary

The DeepSeek Provider serves only the control plane at this time. You cannot assign it to a data-plane Rail. The data plane uses supported dedicated or bounded low-parameter models. Controller distributes only the Models and credentials referenced by active data-plane bindings to Runners. A **model capability binding** in Guardrail Catalog is different from a reusable **Policy** in the Policy Library. The binding supplies a detection dependency. The Policy defines the protection behavior.

The repository's `docs/model-configuration.md` retains detailed deployment and protocol notes.
