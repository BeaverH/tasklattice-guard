平台管理既管理谁能修改配置，也管理不同服务如何认证。不要把一种凭据复制到另一条调用链路里。

<a id="admin-governance" />

## 两种账户角色

| 角色 | 可用功能 |
| --- | --- |
| 用户（`user`） | 护栏设计分组中的护栏、调试场和策略库；集成分组中的路由器和端点。可以创建、修改、测试、发布和管理这些业务资源，并在运行观测中查看运行日志与已采集的请求、响应正文。 |
| 管理员（`admin`） | 仅负责平台设置中的平台健康、执行节点、模型提供商、模型、模型价格、检测器目录 和版本信息；可以管理账户、查看操作审计日志；不能查看租户运行日志与调用正文，不能配置 Guardrail、Policy、路由器或端点。 |

用户侧边栏显示 护栏设计、集成和运行观测，登录后进入护栏列表。运行日志记录请求、响应、检测结果和执行步骤，属于租户使用功能；已采集的请求和响应正文按需展开加载，保留原有采集级别、脱敏和保留规则。操作审计记录谁修改了什么配置，属于平台功能，用户不能通过页面、API 或个人 Token 访问。

管理员登录后进入模型提供商页面，侧边栏按平台职责分为三组：

- 模型与检测：模型提供商、模型（含价格）、检测器目录，配置共享模型服务和业务检测器绑定。
- 平台运行：健康、执行节点和版本，检查服务健康、管理 Runner 并查看软件版本。
- 访问与审计：用户与访问、审计日志，管理身份权限并核对配置操作。

管理员从侧边栏「平台运行」分组直接进入健康、执行节点和版本页面；用户保留侧边栏底部的设置入口及页面内标签导航。两种角色继续使用原有 `/settings/*` 路径。用户和管理员都可修改 Runner 容量目标、移除离线注册记录或强制移除初始化或同步中的注册记录，使用相同的确认流程。正在提供服务的 Runner 仍受保护。通过个人 Token 操作时仍需 `runners:write` 权限。平台 Default 的测试、发布、版本删除和基线切换仍由管理员维护。运行观测分组提供账单入口，按安全护栏查看模型用量和预估费用；原护栏费用链接跳转到账单，护栏列表不再显示本月开销列。模型页面保留模型与价格标签。两种角色都可使用个人账户、密码、Access Tokens 和文档。越权访问页面会显示权限说明，对应 API 同样拒绝访问。

护栏设计所需的模型能力状态通过精简只读接口提供，不包含 Provider 地址、凭据提示、控制面模型配置或测试正文。

角色作用于整个共享工作空间，不划分资源所有权。个人 Access Token 的有效权限是账户当前角色与所选模块权限的交集；切换角色后立即重新计算已有 Token 的有效权限。用户可以授予只读的运行日志权限（包括按需加载的调用正文），不能授予审计日志权限；管理员拥有操作审计权限，不能访问租户运行日志。路由发布原有的审核人与提交人分离规则继续生效。

<a id="credential-types" />

## 四类身份

| 身份或凭据 | 用途 | 不应用于 |
| --- | --- | --- |
| 浏览器 Session | 登录管理控制台、按当前账户权限操作 | 应用的运行时检查 |
| 个人 Access Token | 自动化调用 Controller 管理 API。受账户角色、模块权限和有效期限制。 | 代替 Endpoint 凭据 |
| Endpoint 凭据 | 应用或 AI Gateway 调用 Runner 检测接口。按 Endpoint 隔离。 | 登录控制台或签发个人 Token |
| Runner 控制凭据 | Controller 与 Runner 的受控连接和配置下发 | 业务应用请求 |

<a id="platform-audit" />

## 管理与核对

在[账户与权限](/access)分配管理职责，定期查看个人 Token 的有效期和撤销情况。Endpoint 凭据在创建时只显示一次，应交给对应的应用或网关并按需轮换。配置变更通过[审计日志](/audit-log)核对。请求结果和保护发现，到[运行日志](/logs)查看。审计记录、Runner 健康和业务请求 Decision 分别回答不同的问题，不能互相代替。
