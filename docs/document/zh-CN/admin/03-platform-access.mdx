账户角色控制管理工作区权限，凭据认证不同调用链路。请按任务选择对应角色和凭据。

<a id="admin-governance" />
## 分离业务与平台角色

| 角色 | 主要工作区 | 权限 |
| --- | --- | --- |
| 用户，`user` | 护栏设计、集成和运行观测 | 创建并管理业务 Guardrail、Policy、Router 和 Endpoint，查看运行日志与已采集正文。 |
| 管理员，`admin` | 平台配置、访问与审计 | 配置共享模型、能力绑定和账户，读取操作审计，维护平台 Default 操作。 |

管理员不能修改业务资源或查看租户运行日志。业务用户不能配置共享模型服务或读取操作审计。管理 API 允许时，管理员仍可只读查询业务元数据。

角色作用于共享工作空间，不建立业务资源之间的所有权隔离。

<a id="access-shared-operations" />
### 共享的运行管理权限

两种角色都可查看健康、Runner 状态和软件版本，也可调整容量目标、移除运行规则允许删除的注册记录。正在提供服务的实例仍受保护。个人 Token 写入需具备 `runners:write`。

用户从设置入口进入这些页面，管理员从“平台运行”侧边栏进入。两者继续使用 `/settings/*` 路径。

两种角色都保留个人账户、密码管理、Access Tokens 和文档。用户在[账单](/billing)查看模型用量，管理员在[模型](/settings/models?tab=pricing)管理价格。

设计流程使用精简的能力状态接口，不包含 Provider 地址、凭据提示、控制面模型配置或测试正文。

<a id="access-token-authority" />
### 个人 Token 的有效权限

有效权限取当前账户角色与模块授权的交集，write 包含 read。角色变化后，后续请求会重新计算已有 Token 的权限。

用户可授予运行记录和已采集正文的只读权限，管理员可授予审计读取权限。Token 不能超过所属账户的角色权限。Router 审批还要求审批人与提交人不同。

<a id="credential-types" />
## 按调用链路选择凭据

| 凭据 | 用途 | 边界 |
| --- | --- | --- |
| 浏览器 Session | 按当前账户权限操作控制台。 | 不用于运行时检测。 |
| 个人 Access Token | 在角色、模块和有效期范围内自动调用管理 API。 | 不能签发其他个人 Token。 |
| Endpoint 凭据 | 为单个 Endpoint 认证应用或网关的检测调用。 | 不能登录控制台或修改平台配置。 |
| Runner 控制凭据 | Controller 与 Runner 的控制连接和配置下发。 | 不用于业务检测请求。 |

<a id="platform-audit" />
## 核对权限与操作

管理员在[账户与权限](/access)分配角色。每个账户管理自己的 [Access Tokens](/account/access-tokens)。

Endpoint 凭据仅在签发时展示完整值。业务用户将其交给对应应用，并按需轮换。

管理员在[审计日志](/audit-log)核对配置操作，用户在[运行日志](/logs)查看请求 Decision 和发现。健康与下发状态不等于任一种日志记录。
